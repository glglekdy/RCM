# 리듬게임 채보 에디터 설계

- 작성일: 2026-10-09
- 범위: 공유 코어(`core`, `playfield`) + 데스크톱 채보 에디터(`apps/editor`)
- 범위 밖: 게임 본체(`apps/game`) — 메뉴, 곡 선택, 점수 저장 등은 다음 프로젝트에서 별도 설계

## 0. 목표와 전제

### 사용자가 정한 것
- 직접 만드는 **웹 리듬게임**용 채보 에디터
- **세로 레인형**, 노트는 **일반(tap)·롱노트(hold)** 두 종류
- 레인 수는 **채보마다 다름**, 곡 중간 **BPM 변경 지원**
- 에디터는 게임과 분리된 **데스크톱 프로그램 (Electron + TypeScript)**
- 게임도 이 저장소에서 만들고, 에디터와 코드를 공유
- 첫 버전 기능: 기본 편집, 재생 미리보기, BPM/오프셋 설정, 실시간 녹음, 선택·복사·반전·Undo/Redo, 테스트 플레이, 파형 표시, **탭 BPM**, **가이드 마커**

### 설계에서 정한 것 (변경 가능)
- 레인 수는 4~8
- 곡 폴더 방식 저장
- UI 패널은 React, 타임라인과 플레이 화면은 Canvas 2D
- 지원 오디오는 Chromium이 디코딩할 수 있는 형식 (ogg, mp3, wav)

### 성공 기준
- 음악을 고르고, BPM·오프셋을 맞추고, 노트를 찍거나 녹음해서 저장할 수 있다
- 저장한 채보를 에디터 테스트 플레이로 그대로 쳐볼 수 있다
- 게임은 `core`로 채보를 읽기만 하면 에디터와 같은 타이밍으로 재생된다

## 1. 저장소 구조

npm workspaces 기반 모노레포.

```
RCM/
  package.json            workspaces 설정, 공통 스크립트
  tsconfig.base.json
  packages/
    core/                 채보 포맷 타입, 읽기·검증·저장, 타이밍 계산 (순수 TS, DOM 의존 없음)
    playfield/            노트가 떨어지는 화면 렌더링 + 입력 판정 (Canvas 2D)
  apps/
    editor/               Electron 앱 (electron-vite + React)
    game/                 (다음 프로젝트)
```

의존 방향: `editor → playfield → core`, `editor → core`. `core`는 아무것도 의존하지 않는다.

## 2. 채보 포맷

### 2.1 시간 단위
- 노트와 BPM 변경 지점의 위치는 **tick**(정수)으로 저장한다. **1박 = 480 tick**.
- 480은 2, 3, 4, 6, 8, 12, 16으로 나누어떨어지므로 1/4 ~ 1/32, 셋잇단(1/12, 1/24) 스냅이 모두 정수 tick으로 떨어진다.
- BPM을 고쳐도 노트는 박자 위치에 붙어 있다.
- 가이드 마커만 예외로 **ms**로 저장한다 (박자와 무관한 표시이므로).

### 2.2 곡 폴더

```
songs/<song-id>/
  audio.ogg            음악 파일 (이름은 song.json의 audio 필드가 가리킴)
  song.json            곡 정보 + 타이밍
  <name>.chart.json    난이도별 채보 (여러 개)
  editor.json          에디터 전용 데이터 (가이드 마커). 게임은 읽지 않음
```

### 2.3 song.json

```jsonc
{
  "formatVersion": 1,
  "title": "곡 제목",
  "artist": "아티스트",
  "audio": "audio.ogg",
  "offsetMs": 120,            // 음악 파일에서 tick 0이 위치하는 시간(ms). 음수 허용
  "previewStartMs": 30000,
  "timing": [                 // tick 오름차순. 첫 항목은 반드시 tick 0
    { "tick": 0,     "bpm": 150, "beatsPerMeasure": 4 },
    { "tick": 30720, "bpm": 75 }   // beatsPerMeasure 생략 시 직전 값 유지
  ]
}
```

### 2.4 <name>.chart.json

```jsonc
{
  "formatVersion": 1,
  "name": "HARD",
  "level": 12,
  "lanes": 7,                 // 4~8
  "notes": [                  // tick, lane 오름차순으로 저장
    { "tick": 1920, "lane": 0, "type": "tap" },
    { "tick": 2400, "lane": 3, "type": "hold", "endTick": 3360 }
  ]
}
```

### 2.5 editor.json

```jsonc
{
  "formatVersion": 1,
  "markers": [ { "ms": 15234.5, "label": "" } ]
}
```

### 2.6 검증 규칙 (`core`에서 수행)
- `formatVersion`이 지원 버전이 아니면 오류
- `timing`은 비어 있지 않고, 첫 항목 tick = 0, tick 엄격 오름차순, bpm > 0
- `lanes`는 4~8 정수, 모든 노트의 `lane`은 0 ≤ lane < lanes
- tick ≥ 0 정수, hold는 `endTick > tick`
- 같은 레인에서 노트가 겹치면 오류 (tap 두 개가 같은 tick, 또는 hold 구간 안에 다른 노트)
- 오류는 "어느 파일의 어느 항목이 왜 틀렸는지"를 담은 메시지 목록으로 반환

## 3. core 패키지

| 모듈 | 역할 |
|---|---|
| `types` | `Song`, `Chart`, `Note`, `TimingPoint`, `EditorData` 타입 |
| `parse` / `serialize` | JSON ↔ 타입, 검증 포함. 저장 시 노트 정렬, 들여쓰기 2칸 |
| `timing` | `TimingMap` — `tickToMs(tick)`, `msToTick(ms)` (BPM 변경 반영), 마디/박 경계 나열(그리드 그리기용) |
| `snap` | `snapTick(tick, division)` — 현재 타이밍 구간 기준 가장 가까운 스냅 위치 |
| `tapTempo` | 탭 시각 목록 → BPM·위상 추정 (5.4절) |

`TimingMap`은 timing 배열에서 구간별 시작 ms를 미리 계산해 두고 이진 탐색으로 변환한다.

## 4. playfield 패키지

- 입력: `Chart`, `TimingMap`, 현재 재생 시간(ms) 공급 함수, 설정(노트 속도, 키 배치)
- Canvas에 레인, 판정선, 떨어지는 노트(롱노트는 몸통 포함), 판정 문구, 콤보를 그림
- 판정 창 기본값: Perfect ±40ms, Great ±80ms, Good ±120ms, 그 밖은 Miss
- 롱노트: 시작을 일반 노트처럼 판정. 끝 시간 −120ms 이전에 떼면 Miss, 그 이후까지 누르고 있으면 성공
- 판정 로직(`judge`)은 렌더링과 분리된 순수 함수로 두어 단위 테스트한다
- 에디터 테스트 플레이에서 쓰고, 나중에 게임에서도 그대로 사용

## 5. 에디터 (apps/editor)

### 5.1 프로세스 구성
- **main 프로세스**: 파일 읽기/쓰기, 폴더 선택 대화상자, 창 닫기 전 저장 확인
- **preload**: `contextBridge`로 다음 함수만 노출 — `openSongFolder()`, `createSong(audioPath, destDir)`, `readFile(path)`, `writeFileAtomic(path, data)`, `readAudio(path)`
- **renderer**: React UI + Canvas 타임라인. Node 접근 없음 (`contextIsolation: true`, `nodeIntegration: false`)
- 저장은 같은 폴더의 임시 파일에 쓴 뒤 이름을 바꿔 교체한다 (저장 중 종료돼도 원본 보존)

### 5.2 화면 구성
- **상단 툴바**: 파일(새 곡/열기/저장), 난이도 선택·추가, 스냅 선택, 도구(그리기/선택), 재생 컨트롤, 효과음 볼륨
- **가운데 타임라인**: 세로 방향, 아래 → 위로 시간이 흐름 (게임과 같은 방향)
  - 레인, 마디선(굵게), 박선, 스냅 그리드선
  - 왼쪽에 파형, BPM 변경 지점 표시(BPM 숫자 라벨), 가이드 마커(점선, 별도 색)
  - 재생선(현재 위치)
- **오른쪽 패널**: 곡 정보(제목, 아티스트, 오프셋, 미리듣기 시작), 타이밍 목록(BPM 변경 지점 추가/수정/삭제), 채보 정보(이름, 레벨, 레인 수), 탭 BPM 결과

### 5.3 편집
- **그리기 도구**: 좌클릭하면 스냅 위치에 tap 추가, 좌클릭한 채 위로 드래그하면 hold. 우클릭하면 노트 삭제
- **선택 도구**: 드래그로 사각 범위 선택, Shift+클릭으로 추가 선택. 선택한 노트를 드래그해 이동(스냅 적용, 레인 이동 가능)
- **복사/잘라내기/붙여넣기**: Ctrl+C / Ctrl+X / Ctrl+V. 붙여넣기는 재생선 위치(스냅 적용)에 선택 영역의 첫 노트가 오도록 배치
- **좌우 반전**: 선택한 노트의 lane을 `lanes-1-lane`으로 바꿈
- **삭제**: Delete
- **스냅**: 1/4, 1/8, 1/12, 1/16, 1/24, 1/32 (1/4 = 4분음표 = 1박). 숫자키나 툴바로 전환
- **이동/확대**: 마우스 휠로 스크롤, Ctrl+휠로 세로 확대/축소
- 겹침 규칙(2.6)을 어기는 배치는 막는다 (그 자리에 노트를 추가하지 않음)
- 레인 수를 바꿀 때 범위를 벗어나는 노트가 있으면 경고하고 확인을 받은 뒤 삭제

### 5.4 Undo/Redo
- 모든 편집은 `Command { do(state), undo(state) }`로 실행되고 히스토리 스택에 쌓인다
- 대상: 노트 추가/삭제/이동/반전/붙여넣기, 타이밍 변경, 오프셋 변경, 곡/채보 정보 변경, 마커 추가/삭제, 녹음 한 번(묶음)
- Ctrl+Z / Ctrl+Y (Ctrl+Shift+Z). 히스토리는 채보별로 관리하고 저장해도 유지
- 편집 상태(명령, 선택, 클립보드)는 React와 분리된 순수 TS 모듈로 두어 단위 테스트한다

### 5.5 재생
- Space: 재생/정지. 재생 시작 위치 = 재생선
- 오디오는 `AudioContext.decodeAudioData`로 전체를 디코딩해 `AudioBufferSourceNode`로 재생
- **시계는 `AudioContext.currentTime` 하나만 기준**으로 삼는다. 재생 위치(ms) = (currentTime − 시작 시각) × 1000 + 시작 오프셋. 화면은 requestAnimationFrame마다 이 값을 읽어 그린다
- 효과음: 재생선이 노트(hold는 시작)를 지날 때 짧은 효과음 버퍼를 같은 AudioContext에서 미리 예약 재생(100ms 앞을 내다보고 스케줄링)
- 재생 중 타임라인은 재생선이 화면 아래쪽 1/4 높이에 고정되도록 자동 스크롤

### 5.6 BPM / 오프셋
- 오른쪽 패널에서 오프셋(ms) 직접 입력, ±1ms / ±10ms 버튼
- 재생선 위치(스냅 적용)에 BPM 변경 지점 추가, 목록에서 BPM·박자 수정/삭제 (tick 0 지점은 삭제 불가)
- 타이밍이 바뀌면 노트는 tick을 유지한다 (ms 위치가 따라 움직임)

### 5.7 탭 BPM
- 재생 중 `T` 키를 박자에 맞춰 친다. 각 탭의 재생 위치(ms)를 기록
- 마지막 탭 후 2초 넘게 입력이 없으면 새 탭 세션으로 초기화
- 탭이 4번 이상이면 계산: 탭 순번 i와 시각 tᵢ의 선형 회귀로 박 간격 `beatMs`(기울기)와 위상(절편)을 구한다. `BPM = 60000 / beatMs` (소수 둘째 자리 반올림), 편차(잔차 표준편차 ms)도 표시
- 오른쪽 패널에 "BPM 150.21 · 첫 박 118ms · 편차 6ms · 탭 12회"와 버튼 두 개를 보여 준다
  - **곡 전체에 적용**: timing을 `[{tick:0, bpm}]` 하나로 바꾸고, `offsetMs`를 첫 탭 이전의 가장 이른 박 위치(위상을 beatMs로 나눈 나머지)로 설정
  - **이 지점부터 적용**: 첫 탭 시각을 현재 타이밍 기준 tick으로 바꿔 가장 가까운 박에 맞추고, 그 tick에 BPM 변경 지점을 추가(이미 있으면 BPM 수정)
- 적용은 Undo 한 번으로 되돌릴 수 있다

### 5.8 가이드 마커
- 재생 중(또는 정지 중) `M` 키를 누르면 그 순간의 재생 위치(ms)에 마커 추가. 스냅을 적용하지 않음
- 타임라인에 점선으로 표시, 우클릭하면 삭제, 오른쪽 패널 목록에서 라벨 편집
- `[` / `]` 키로 이전/다음 마커로 재생선 이동
- `editor.json`에 저장. 곡 단위(모든 난이도 공통)

### 5.9 실시간 녹음
- 녹음 버튼(또는 `R`)으로 녹음 모드를 켜고 재생
- 레인 키 기본 배치 (테스트 플레이와 공통):

  | 레인 수 | 키 |
  |---|---|
  | 4 | D F J K |
  | 5 | D F Space J K |
  | 6 | S D F J K L |
  | 7 | S D F Space J K L |
  | 8 | A S D F J K L ; |

- 키를 누른 시각과 뗀 시각을 기록 → 정지할 때 현재 스냅으로 tick 정렬
- 누른 길이가 현재 스냅 한 칸 이상이면 hold, 아니면 tap
- 기존 노트와 겹치면 기존 노트를 유지하고 새 노트를 버린다. 버린 개수를 알려 줌
- 녹음 한 번 = Undo 한 번
- 녹음 모드에서는 레인 키 외의 편집 단축키(`T`, `M`, 숫자키 등)를 끈다. 5키·7키는 Space가 레인 키이므로 녹음 중 정지는 Esc로 한다

### 5.10 테스트 플레이
- `F5`: 재생선 위치부터 시작, `Shift+F5`: 처음부터 시작
- 에디터 화면 위에 `playfield`를 전체 화면으로 띄움. 같은 AudioContext 시계를 사용
- 판정·콤보 표시, 노트 속도 조절(위/아래 화살표), Esc로 편집 화면 복귀(재생선은 시작 위치로 돌아감)
- 테스트 플레이 결과는 저장하지 않음

### 5.11 파형
- 오디오를 디코딩한 뒤 채널 평균의 절대값 최대치를 일정 구간(예: 256샘플)마다 미리 계산해 둔다
- 타임라인 왼쪽 띠에 현재 확대 비율로 그린다. 확대/축소 시에는 미리 계산한 값을 묶어서 사용

### 5.12 파일 작업
- **새 곡**: 음악 파일 선택 → 곡 폴더 위치 선택 → 폴더 생성, 음악 복사, 기본 `song.json`(BPM 120, 오프셋 0)과 빈 `normal.chart.json`(4키) 생성
- **열기**: 곡 폴더 선택 → `song.json`, 모든 `*.chart.json`, `editor.json`(없으면 빈 값) 읽기
- **난이도 추가**: 이름·레인 수 입력 → 새 chart 파일
- **저장**: Ctrl+S로 변경된 파일만 저장. 제목 표시줄에 저장 안 된 변경 표시(`*`)
- 창을 닫을 때 저장 안 된 변경이 있으면 저장/버리기/취소 대화상자

### 5.13 오류 처리
- JSON 문법 오류, 검증 실패, 지원하지 않는 `formatVersion`: 열기를 중단하고 오류 목록을 대화상자로 보여 줌
- 오디오 디코딩 실패: 오류를 표시하고 곡을 열지 않음
- 저장 실패(권한 등): 오류를 표시하고 편집 상태는 그대로 유지

## 6. 테스트

- **core** (Vitest): tick↔ms 변환(단일·복수 BPM, 음수 오프셋), 마디/박 경계 나열, 스냅, 탭 BPM 회귀, parse/serialize 왕복, 검증 실패 케이스 하나씩
- **editor 편집 로직** (Vitest): 각 Command의 do/undo, 붙여넣기 위치, 반전, 겹침 차단, 녹음 정렬(tap/hold 구분, 겹침 버리기), 탭 BPM 적용 두 가지
- **playfield judge** (Vitest): 판정 창 경계값, 롱노트 일찍 뗌/끝까지 누름, 지나간 노트 Miss 처리
- **앱**: 각 단계가 끝날 때 실제로 실행해서 해당 기능을 손으로 확인

## 7. 진행 단계

| 단계 | 내용 | 끝나면 할 수 있는 것 |
|---|---|---|
| 1 | 모노레포 구성 + `core` (포맷, 검증, 타이밍, 스냅) | 테스트로 포맷과 계산 검증 |
| 2 | 에디터 기본: 새 곡/열기, 타임라인 그리기, 재생, 효과음, BPM/오프셋 편집 | 음악을 틀고 그리드가 박자에 맞는지 확인 |
| 3 | 탭 BPM + 가이드 마커 | 키를 쳐서 BPM·오프셋을 잡고 마커 표시 |
| 4 | 노트 편집 + 스냅 + 저장 + Undo/Redo + 선택/복사/반전 | 채보를 만들고 저장 |
| 5 | 파형 표시 | 박자 맞추기가 쉬워짐 |
| 6 | 실시간 녹음 | 키보드로 채보 찍기 |
| 7 | `playfield` + 테스트 플레이 | 에디터 안에서 직접 플레이 |

## 8. 이번 범위에서 하지 않는 것
- 게임 본체(곡 선택, 점수, 설정 저장)
- 재생 속도 조절(0.5배속 등), 키 배치 사용자 설정
- 노트 종류 추가(슬라이드, 플릭 등), 변속/스크롤 속도 이벤트
- 다른 게임 포맷 가져오기/내보내기
