# 이름 붙은 트랙 (Named Tracks) 설계

- 작성일: 2026-10-10
- 기반: `docs/superpowers/specs/2026-10-09-chart-editor-design.md` (이하 "기존 스펙")
- 이 문서는 기존 스펙의 "레인 수(4~8) + 레인 번호" 모델을 "이름 붙은 트랙" 모델로 대체한다. 여기서 다루지 않는 내용은 기존 스펙을 따른다.

## 0. 목표

### 사용자가 정한 것
- 노트가 레인 번호 대신 **트랙 이름 문자열**(예: `Note_1`, `Side_L`, `Trigger_1`)을 가리킨다. 같은 에디터로 여러 게임용 채보를 만들고, 게임은 트랙 이름으로 노트를 해석한다
- 트랙 구성은 **프리셋**으로 앱에 저장하고, 난이도를 만들 때 고른 프리셋의 트랙 목록을 채보에 복사한다. 채보마다 트랙을 직접 편집할 수도 있다
- 트랙마다 **색과 폭**을 지정한다 (겹치는 트랙은 지원하지 않음)
- 녹음·테스트 플레이 키는 **프리셋의 트랙별 키**를 쓴다
- 예전 포맷(`lanes`, `lane`)은 지원하지 않는다 (만든 채보가 없음)
- 사이드 트랙 기본 이름은 `Side_L`(왼쪽), `Side_R`(오른쪽)

### 설계에서 정한 것
- 노트는 트랙을 **이름 문자열**로 가리킨다 (배열 번호가 아님): 파일을 읽기 쉽고, 트랙 순서를 바꿔도 노트가 바뀌지 않는다
- 아직 공개된 파일이 없으므로 `formatVersion`은 1을 유지하고 버전 1의 정의를 바꾼다

### 성공 기준
- 프리셋을 골라 4K 채보와 `6K + 사이드` 채보를 만들고, 각각 노트를 찍고·녹음하고·테스트 플레이할 수 있다
- 채보 파일만 보고 어떤 트랙이 있는지 알 수 있다
- 트랙 이름을 바꾸거나 순서를 바꿔도 노트가 올바른 트랙에 남는다

## 1. 채보 포맷 (기존 스펙 2.4, 2.6 대체)

```jsonc
{
  "formatVersion": 1,
  "name": "HARD",
  "level": 12,
  "tracks": [                                        // 화면 순서 = 배열 순서
    { "id": "Side_L", "color": "#f59e0b", "width": "wide" },
    { "id": "Note_1" }, { "id": "Note_2" }, { "id": "Note_3" },
    { "id": "Note_4" }, { "id": "Note_5" }, { "id": "Note_6" },
    { "id": "Side_R", "color": "#f59e0b", "width": "wide" }
  ],
  "notes": [
    { "tick": 1920, "track": "Note_1", "type": "tap" },
    { "tick": 2400, "track": "Side_L", "type": "hold", "endTick": 3360 }
  ]
}
```

### 1.1 트랙
| 필드 | 필수 | 규칙 |
|---|---|---|
| `id` | 필수 | 정규식 `^[A-Za-z0-9_-]{1,32}$`. 한 채보 안에서 유일 (대소문자 구분) |
| `color` | 선택 | `#rrggbb` 형식. 생략 시 기본 노트 색 `#f2f2f2` |
| `width` | 선택 | `narrow` \| `normal` \| `wide`. 생략 시 `normal` |

- 트랙 수는 1~16개
- 직렬화할 때 `color`, `width`가 기본값이면 생략한다

### 1.2 노트
- `lane` 대신 `track: string`
- 노트 키(선택·겹침 판정용 식별자): `` `${track}:${tick}` ``

### 1.3 검증 (기존 2.6의 레인 관련 규칙 대체)
- `tracks`는 1~16개, 각 트랙은 1.1 규칙을 지킨다. 이름이 겹치면 오류
- 모든 노트의 `track`은 `tracks`에 있는 이름이어야 한다
- 겹침 검사는 트랙별로 한다 (규칙은 기존과 같음: 같은 tick의 두 노트, 또는 hold 구간 안의 다른 노트)
- `lanes` 필드가 있거나 노트에 `lane`이 있으면 "예전 포맷은 지원하지 않아요" 오류
- 오류 메시지 형식은 기존과 같다 (`hard.chart.json › tracks[2].id: ...`)

### 1.4 정렬
- 노트는 tick 오름차순, 같은 tick이면 `tracks` 배열 순서

## 2. 트랙 프리셋

### 2.1 데이터 (앱 설정 `settings.json`에 저장, 채보 파일에는 들어가지 않음)
```jsonc
{
  "presets": [
    {
      "id": "6k-side",                 // 내부 식별자 (자동 생성)
      "name": "6K + 사이드",
      "tracks": [
        { "id": "Side_L", "color": "#f59e0b", "width": "wide", "key": "ShiftLeft" },
        { "id": "Note_1", "key": "KeyS" }, ...
        { "id": "Side_R", "color": "#f59e0b", "width": "wide", "key": "ShiftRight" }
      ]
    }
  ]
}
```
- `key`는 `KeyboardEvent.code` 값. 한 프리셋 안에서 키가 겹치면 저장할 수 없다. 키가 비어 있는 트랙은 허용 (녹음·플레이에서 그 트랙은 칠 수 없음)
- 프리셋 트랙도 1.1 규칙을 따른다

### 2.2 기본 프리셋
설정에 `presets`가 없으면(첫 실행) 다음을 만든다. "기본값 복원"은 이 목록으로 되돌린다(확인 후 덮어쓰기).

| 이름 | 트랙 → 키 |
|---|---|
| 4K | Note_1~4 → D F J K |
| 5K | Note_1~5 → D F Space J K |
| 6K | Note_1~6 → S D F J K L |
| 7K | Note_1~7 → S D F Space J K L |
| 8K | Note_1~8 → A S D F J K L ; |
| 6K + 사이드 | Side_L → 왼쪽 Shift, Note_1~6 → S D F J K L, Side_R → 오른쪽 Shift. Side_L/R은 `#f59e0b`, `wide` |

### 2.3 프리셋 관리 화면
- 시작 화면 왼쪽 메뉴에 `홈` 아래로 `트랙 프리셋` 메뉴 추가
- 왼쪽: 프리셋 목록 + `새 프리셋`, `복제`, `삭제`, `기본값 복원`
- 오른쪽: 선택한 프리셋의 이름 입력칸과 트랙 표
  - 행: 순서 이동(위/아래), id 입력, 색(스와치 + `#rrggbb` 입력), 폭(세그먼트 버튼: 좁게/보통/넓게), 키(클릭하면 "키를 누르세요" 상태 → 다음 키 입력으로 지정, Esc 취소, Backspace/Delete로 비움), 삭제
  - `트랙 추가`: 다음 빈 이름 `Note_N`으로 추가
  - 규칙 위반(이름 중복·형식, 키 중복)은 해당 칸에 `--danger` 표시. 위반이 있으면 저장하지 않는다
- 편집은 바로 설정 파일에 저장한다 (입력칸은 blur/Enter 시)
- 프리셋은 최소 1개 남아야 한다 (마지막 하나는 삭제 불가)

## 3. 채보 만들기와 편집

### 3.1 새 프로젝트 창 / 난이도 추가 창 (기존 5.2.1, 5.13 변경)
- `첫 난이도 레인 수` 세그먼트 버튼 → **`트랙 프리셋`** 드롭다운. 기본값은 마지막으로 고른 프리셋 (없으면 `4K`)
- 드롭다운 아래에 트랙 미리보기: 트랙 이름을 색·폭이 반영된 작은 칩으로 나열
- 만들 때 프리셋 트랙의 `id`, `color`, `width`만 채보에 복사한다 (`key`는 복사하지 않음)
- main 프로세스의 `createProject` 옵션은 `lanes: number` 대신 `tracks: Track[]`를 받는다

### 3.2 채보 탭 (기존 5.3 오른쪽 패널의 "레인 수" 대체)
- 이름, 레벨 아래에 **트랙 카드**
  - 행: 순서 이동, id 입력, 색, 폭, 삭제 (프리셋 표와 같은 모양, 키 칸 없음)
  - `트랙 추가`
  - `프리셋으로 저장`: 이름을 입력받아 현재 트랙 목록 + 현재 키 배치(3.4)로 새 프리셋 생성
- 동작과 Undo 라벨
  - 추가 (`트랙 추가`)
  - 이름 변경 (`트랙 이름 변경`): 그 트랙의 모든 노트의 `track`도 같이 바꾼다. 형식이 틀리거나 이미 있는 이름이면 거부하고 원래 값으로 되돌린다
  - 순서 변경 (`트랙 순서 변경`): 노트는 그대로
  - 색·폭 변경 (`트랙 모양 변경`)
  - 삭제 (`트랙 삭제`): 노트가 있으면 "N개 노트가 함께 삭제돼요" 확인. 마지막 트랙은 삭제 불가
- 그 아래 **키 배치** 카드 (읽기 전용): 트랙별 키 라벨과 출처 문구("프리셋 '6K + 사이드'의 키" 또는 "자동 배정")

### 3.3 편집 동작 변경
| 기존 | 변경 |
|---|---|
| 레인 = 0..lanes-1 | 트랙 = `tracks` 배열 위치. 노트에는 이름 저장 |
| 좌우 반전 `lane → lanes-1-lane` | 트랙 위치 `i → n-1-i`의 트랙 이름으로 교체 |
| 선택 노트 이동 dLane | 트랙 위치 이동. 범위를 벗어나면 거부 |
| 붙여넣기: 레인 범위 넘으면 거부 | 클립의 트랙 이름이 지금 채보에 없으면 거부, 토스트 `여기에는 붙여넣을 수 없어요 (겹치거나 없는 트랙이 있어요)` |
| 사각 선택 lane0~lane1 | 트랙 위치 범위 |
| `setChartLanes` (레인 수 변경) | 삭제. 3.2의 트랙 편집 명령으로 대체 |

### 3.4 키 배치 결정 (녹음·테스트 플레이)
순서대로 적용:
1. 채보의 트랙 id 목록과 **id 집합이 같은** 프리셋 중 첫 번째 → 그 프리셋의 트랙별 키 (순서가 달라도 id로 매칭)
2. 없으면 **자동 배정**: 트랙 순서대로 `KeyA KeyS KeyD KeyF KeyJ KeyK KeyL Semicolon KeyQ KeyW KeyE KeyR KeyU KeyI KeyO KeyP`
- 키가 없는 트랙은 녹음·플레이에서 칠 수 없다 (테스트 플레이에서는 그 트랙 노트가 Miss로 처리됨)
- 결정 함수는 순수 함수로 두어 테스트한다: `resolveKeymap(tracks, presets) → { keys: Map<trackId, code | null>, source: { kind: 'preset', name } | { kind: 'auto' } }`

## 4. 화면 그리기

### 4.1 에디터 타임라인 (기존 5.3, 6.3 변경)
- 트랙 폭: `narrow` 32px, `normal` 48px, `wide` 80px. 트랙 영역 전체 너비 = 폭의 합, 가운데 정렬
- 트랙 바탕은 기존 레인 바탕, 구분선은 기존 레인 구분선 색
- 노트 색 = 트랙 `color` (없으면 `#f2f2f2`). 롱노트 몸통은 같은 색 60% 투명도
- 타임라인 맨 위에 트랙 이름 라벨 줄(높이 20px, 12px `--text-muted`, 폭이 좁아 안 들어가면 말줄임)
- 녹음 중 키 라벨은 3.4의 키 배치를 쓴다
- 미니맵도 같은 폭 비율과 트랙 색으로 노트를 그린다

### 4.2 테스트 플레이 (`playfield`)
- 트랙 폭: 기본 64px × (`narrow` 0.67 / `normal` 1 / `wide` 1.67)
- 노트 색 = 트랙 색
- 트랙 아래 키 라벨은 3.4의 키 배치. 키 없는 트랙은 `-`
- `Playfield` 옵션에 `keymap: Map<string, string | null>`(트랙 id → code)을 받는다. 기존 `LANE_KEYS` 고정 표는 삭제

## 5. 영향받는 부분

- **core**: `Track` 타입, `Chart.tracks`, `Note.track`, `noteKey`, 검증·정렬·직렬화. `MIN_LANES`/`MAX_LANES` → `MIN_TRACKS = 1`/`MAX_TRACKS = 16`, `TRACK_ID_PATTERN`, `DEFAULT_NOTE_COLOR`, `TRACK_WIDTHS`
- **playfield**: `keymap.ts`를 프리셋 기반 키 결정(3.4)과 기본 키 줄로 교체, `PlayState`·`Playfield`가 트랙 id 사용
- **editor main**: settings에 `presets`, `lastPresetId`; 프리셋 읽기/쓰기 IPC; `createProject`의 `tracks` 옵션; 최근 목록 요약을 `{ name, trackCount }`로
- **editor renderer**: 시작 화면 메뉴 + 프리셋 페이지, 새 프로젝트·난이도 추가 창, 채보 탭 트랙 카드·키 배치 카드, 타임라인 레이아웃·hit-test·그리기, 편집 명령(노트·반전·이동·붙여넣기·사각 선택), 녹음, 미니맵
- **최근 목록**: 난이도 칸 `NORMAL 4K` → `NORMAL · 6트랙`

## 6. 테스트
- core: 트랙 검증(이름 형식·중복·개수·없는 트랙 참조·예전 포맷 거부), 트랙별 겹침, 정렬(같은 tick은 트랙 순서), 직렬화에서 기본값 생략, 왕복
- 키 배치: 집합이 같은 프리셋 매칭(순서 달라도), 매칭 없으면 자동 배정, 16개 트랙 자동 배정, 키 없는 트랙
- 프리셋: 기본 프리셋 생성, 키 중복·이름 규칙 검사, 마지막 프리셋 삭제 거부
- 편집 명령: 트랙 추가/이름 변경(노트 동반 변경, 중복 거부)/순서 변경/삭제(노트 동반 삭제, 마지막 트랙 거부), 반전(사이드 포함 8트랙), 이동 범위, 붙여넣기 없는 트랙 거부
- 레이아웃: 폭 합계와 가운데 정렬, x → 트랙 위치 변환(폭이 다른 트랙 경계)
- 기존 테스트는 새 포맷으로 고친다

## 7. 범위 밖
- 다른 트랙 위에 걸치는(겹치는) 트랙
- 트랙별 노트 종류 제한 (모든 트랙에서 tap·hold 가능)
- 예전 포맷 변환
- 게임별 내보내기 형식
