# 배속 플레이 설계

- 작성일: 2026-11-13
- 기반: `docs/superpowers/specs/2026-10-09-chart-editor-design.md` (5.11절 테스트 플레이)
- 이 문서는 테스트 플레이에서 곡 자체를 느리게·빠르게 재생하는 "배속 플레이"를 추가한다.

## 0. 목표

### 사용자가 정한 것
- 이름은 **배속 플레이**
- **테스트 플레이에서만** 쓴다
- 범위는 **0.1배 ~ 5.0배**
- 음정은 유지하지 않는다 (아래 접근 A)

### 제안해서 승인받은 것
- 0.1 단위로 조절, 기본 1.0
- 판정 범위는 **실제 시간 기준**으로 유지 (PERFECT ±40ms는 몇 배에서든 실제 ±40ms)
- 곡이 빨라진 만큼 노트도 빨리 내려온다. 보이는 빠르기는 기존 배속(↑/↓)으로 따로 맞춘다
- 앱을 켜 둔 동안만 값을 기억한다. 다시 켜면 1.0
- 편집 화면 재생은 항상 1.0

### 하지 않는 것
- 음정 유지(타임 스트레치)
- 편집 화면 재생·녹음의 속도 조절
- 설정 파일 저장 (설정 API·Electron main·웹 저장소를 건드리지 않는다)
- 채보 포맷 변경

### 이러면 실패
- 배속 플레이 값에 따라 음악과 노트가 어긋난다
- 1.0배에서 기존과 동작이 달라진다 (판정, 싱크, 준비 시간)
- 테스트 플레이를 나온 뒤 편집 화면 재생이 1.0배가 아니다

### 성공 기준
- 테스트 플레이 중 값을 바꾸면 끊김 없이 음악과 노트가 같이 빨라지거나 느려진다
- 0.1배와 5.0배에서 자동 플레이(F4)가 전부 PERFECT를 낸다
- F5(다시 시작)는 값을 유지한다

## 1. 접근

| | A. 재생 속도만 바꾼다 (선택) | B. 음정 유지 |
|---|---|---|
| 방법 | `AudioBufferSourceNode.playbackRate` | 타임 스트레치 라이브러리 추가 |
| 소리 | 빠르면 음이 높아지고 느리면 낮아진다 | 자연스럽지만 0.1·5.0 근처에서 뭉개진다 |
| 싱크 | 지금 시계 구조 그대로, 샘플 단위로 정확 | 음악·노트 시계를 새로 맞춰야 한다 |
| 작업량 | `AudioEngine` 중심의 작은 변경 | 몇 배 |

범위가 0.1~5.0으로 넓어 B는 양 끝에서 어차피 소리가 깨진다. 사용자가 A를 골랐다.

## 2. 동작

### 시계 (`AudioEngine`)
- 엔진에 재생 속도 `rate`를 둔다 (기본 1). `setRate(rate)`로 재생 중에도 바꾼다.
- 곡 위치 = 기준 위치 + (지금 ctx 시각 − 기준 ctx 시각) × `rate`. 속도를 바꾸면 그 순간의 위치를 새 기준으로 잡는다 (위치가 튀거나 뒤로 가지 않는다).
- 음악 소스의 `playbackRate`를 같은 순간에 같은 값으로 맞춘다.
- 준비 시간(음수 위치)에는 음악이 아직 예약 상태다. 이때 속도를 바꾸면 음악 시작 시각을 다시 잡아 곡 위치 0에서 정확히 시작하게 한다.
- 효과음 예약(`tick`)도 곡 시각 → ctx 시각 변환에 `rate`를 쓴다. (테스트 플레이는 효과음을 끄지만 계산은 맞춰 둔다.)
- `SmoothClock`은 ctx 시각만 다루므로 그대로 쓴다.

### 테스트 플레이
- 시작·다시 시작할 때 현재 배속 플레이 값으로 엔진 속도를 맞추고, 나올 때 1.0으로 되돌린다.
- 준비 시간은 **실제 1.5초**를 유지한다 (곡 시간으로는 1500ms × `rate`).
- 값은 `speedStore.ts`와 같은 모양의 모듈에 담되 저장은 하지 않는다. `clampRate`로 0.1~5.0, 0.1 단위 반올림.

### 판정 (`@rcm/playfield`)
- `Playfield`·`FreePlayfield`에 `rate` 옵션과 `setRate`를 둔다 (기본 1).
- 판정 상태는 곡 시각으로 견주므로, 실제 시간 기준인 값은 곡 시간으로 바꿔 쓴다: 판정 범위(`JUDGE_WINDOWS`), `HOLD_RELEASE_TOLERANCE`, 판정 보정(`judgeOffsetMs`) 모두 × `rate`.
- 판정 글자·히트 이펙트처럼 곡 시계로 흐르는 연출은 실제 시간 빠르기로 보이게 한다 (0.1배에서 10배 길어지지 않게).
- `rate`가 1이면 기존 계산과 완전히 같다.

### 화면·조작 (`PlaytestOverlay`)
- PC: HUD에 `배속 플레이 2.0x (←/→)`를 기존 `배속 6.5 (↑/↓)` 옆에 표시. ←/→로 0.1씩.
- 폰: `플레이 −` `2.0x` `플레이 +` 버튼을 기존 배속 버튼 옆에.
- 사용자 가이드(`UserGuidePage.tsx`)의 테스트 플레이 설명에 한 줄 추가.

## 3. 만드는 사람에게 맡기는 것
- ←/→가 키 설정(프리셋)과 겹치는 경우의 처리. 기존 ↑/↓와 같은 방식이면 된다.
- 판정 범위를 `rate`에 맞추는 구체적 구조 (판정 상태에 값을 넘길지, 시각을 변환할지).
- 폰 HUD 버튼 문구·배치의 세부.
- 테스트: 엔진 위치 계산(속도 변경 전후 연속성), `clampRate`, 판정 범위 스케일, 1.0배 회귀.
